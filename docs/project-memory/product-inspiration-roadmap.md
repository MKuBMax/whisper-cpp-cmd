# 产品灵感与路线修正

调研的最大洞察是：WhisperCppCmd 的转写后处理相对空白，而竞品普遍有确定性的本地文本处理，例如术语、数字、标点、空格、filler 和 autocorrect。

## 当前更值得做的方向

- 先做有真实样本支撑的独立 quick win。
- 如果后处理需求再次出现，先用薄包装和离散 pass，不要在第一个 pass 出现前搭复杂通用容器。
- 保持所有默认处理本地、确定性和可关闭。
- perf.jsonl 已经为后续统计面板提供数据基础。

## 已经做出的路线修正

- whisper.cpp 当前默认已经启用 flash attention，不再添加无效的 -fa 旋钮。
- 用户否决固定错误词到正确词的 replacements 方案；这不等于模型微调。
- 数字先采用 transcription prompt 偏置，用户实测可用；不做事后 cn2an 盲转，避免破坏成语和自然表达。
- 不做强制云端 LLM、常驻 VAD、多引擎维护和会议分离。
- 音频自愈已经完成生产验证；采样率失配假设已被数据否决，音频方向暂时收手。

## 评估新想法的顺序

先问：

1. 是否解决用户已经确认的痛点？
2. 是否能用当前依赖完成？
3. 是否有测试样本和可逆开关？
4. 是否会扩大单人维护范围？

如果只是为了竞品功能对齐、没有真实反馈，不应立刻进入代码。
