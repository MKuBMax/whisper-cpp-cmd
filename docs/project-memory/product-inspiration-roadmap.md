# 产品灵感与路线修正

调研的当前结论是：先保持 WhisperCppCmd 的识别链路简单稳定，把发布体验和可观测性做好，再根据真实反馈决定是否增加新的文本处理能力。

## 当前更值得做的方向

- 先做有真实样本支撑的独立 quick win。
- perf.jsonl 已经为后续统计面板提供数据基础。
- 首次启动向导、设置窗口、统计面板、GitHub Release 更新检查和可配置的 Developer ID 签名/公证已经接入。

## 已经做出的路线修正

- whisper.cpp 当前默认已经启用 flash attention，不再添加无效的 -fa 旋钮。
- 不在转写结果内部根据用户修正自动固化 replacements；更智能的纠错留给后续小模型方案评估。
- 数字先采用 transcription prompt 偏置，用户实测可用；不做事后 cn2an 盲转，避免破坏成语和自然表达。
- 不做强制云端 LLM、常驻 VAD、多引擎维护和会议分离。
- 音频自愈已经完成生产验证；采样率失配假设已被数据否决，音频方向暂时收手。

## 评估新想法的顺序

先问：

1. 是否解决用户已经确认的痛点？
2. 是否能用当前依赖完成？
3. 是否有测试样本和可逆开关？
4. 是否会扩大单人维护范围？

如果只是为了竞品功能对齐、没有真实反馈，不应立刻进入代码；已经落地的能力也必须保持显式开关和可回退。
