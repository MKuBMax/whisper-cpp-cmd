# 扬声器音乐串扰与系统音频参考消除

用户实测确认：内置扬声器播放音乐或视频人声时，串入内置麦克风，明显降低转写成功率。

## 维护禁区（2026-09-13 真机验收后冻结）

2026-09-13 用户确认「现在没有问题了」。常驻采集 + 频点相干压残差是背景消除的关键方案，不是试验田。

不要在没有新的真机失败证据时改这些边界：

- 不要改回按键时冷启动 / 停掉 ScreenCaptureKit。第二次建流会吐全零。
- 不要改回块级能量门控或单增益时域相减。视频人声会漏进 Whisper。
- 不要用整帧 NLP（-30dB）压残差。人声叠人声时会把近端打死。
- 不要用麦克风/回声能量比做双讲检测。会误判，导致 nlp=0、背景人声漏出。
- 不要先峰值归一化再消除，也不要把残差峰值拉满。
- 不要用 `CMSampleBufferGetDataBuffer` 取 PCM，不要 L+R 平均。
- 不要为假设场景引入重依赖或 VPIO。
- 不要在停麦之前切 sysref 段。参考先结束、麦还在录，句尾对不齐。
- 参考比麦长时不要 `r[:n]` 从前面截。预滚在开头，那样会丢掉结尾。负 lag 必须从完整参考取 `r[start:start+n]`。

要动 `core/sysref.py`、`core/sysref_capture.swift`、`core/ref_cancel.py` 或 pipeline 接入顺序，先读本文再改，改完必须真机：扬声器放人声视频，不说话应接近无识别；说话应主要是近端。连录两次，第二次 `ref_rms` 不能为 0。

## 调研结论

- FFT 谱降噪对音乐/人声串音基本无效。
- whisper-server 没有可直接解决该问题的降噪开关。
- sounddevice/PortAudio 不能直接打开 macOS Voice Processing。
- VPIO/AEC 未采用：本机播放的是第三方内容，不是自身引擎播放。
- 录音中改系统音量（ducking）会打断用户，已删除。

## 关键方案（2026-09-13 真机确认）

常驻采集 + STFT 维纳 + **按频点相干压残差**。这是背景音乐和背景人声共用的消除方案。

- 采集：开关打开且当前是扬声器时，Swift helper `core/sysref_capture` 预热并一直跑。录音只 `begin_segment`/`end_segment` 切段，带 250ms 预滚。构建见 `core/SYSREF_BUILD.md`。
- 取声：AudioBufferList 第一声道。不要 `CMSampleBufferGetDataBuffer`（macOS 26 上常是空缓冲），不要 L+R 平均（立体声反相会抵成静音）。
- 消除：`core/ref_cancel.py`。互相关对齐，STFT 平滑维纳，残差乘 `(1-coh)^2`：相干高的频点是串音，不相干的是近端。在峰值归一化之前做；残差峰值低于 0.02 不再拉满。
- 时间轴：麦和系统参考不是同一块时钟，也不是从零点 1:1。参考段带 250ms 预滚，日志里 `lag≈-250ms~-330ms` 是预滚平移量。对齐必须用完整参考；麦克风停后再 `end_segment`。不变速拉伸。
- 失败回退原声。耳机输出不预热、本段跳过（建流会让蓝牙音乐顿一下）。
- 开关：菜单栏「系统音频参考消除」，`ref_cancel` 持久化。DEV 与正式版权限隔离。

## 已踩过的坑

- 按键冷启动：ready 约 200–400ms，第二次建流经常 8 秒全零。
- 块级能量门 + 峰值归一化：视频人声衰减后仍会被 Whisper 转写，残差还会被拉满。
- 单增益时域相减：扬声器到麦是有色通路，gain≈0.08 消不掉人声（2026-09-13 实测 erle 不足，`text_len=13/48`）。
- 时延搜索只有 200ms：估到窗口边界，对不齐。
- 双讲：整帧 NLP（-30dB）会把近端人声打死；能量双讲检测又会误判，导致 nlp=0、背景人声漏进模型。按频点相干压残差：相干高的是串音，不相干的是近端。
- 参考/麦时间轴（2026-09-14）：两路独立采集（麦 16 kHz，sysref 48 kHz 再抽到 16 kHz）。预滚在参考开头，松开时若先切 sysref 再停麦，参考比麦短一截。若再把长参考 `r[:麦克风长度]` 截掉尾巴，互相关估出 -300ms 也救不回句尾串音。2026-09-14 真机：先停麦再切段、负 lag 从完整参考取齐后，句尾串音明显好转。`lag` 仍约 -300ms 是预滚，不是没对齐。
